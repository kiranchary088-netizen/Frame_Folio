## 1. Project Overview

**FrameFolio – ClickClash Contest** is a complete campus photography contest platform.  
Participants can join the contest, submit original photographs, and vote.  
An organizer can approve/reject members and photos, control contest settings, and manage the leaderboard.

The application is deliberately built as a pure frontend system (HTML + CSS + JavaScript only) as required for this mini-project, while still demonstrating strong software engineering practices.

  - `helpers.js` – pure utilities
  - `art.js` – SVG generator + palette
  - `store.js` – DataStore class (data layer)
  - `auth.js` – authentication
  - `voting.js` – voting engine
  - `ui.js` – rendering layer
  - `main.js` – bootstrap
- Consistent naming, JSDoc-style comments, and clear separation of concerns.

### 4.3 System Design & Architecture
Even though the project is client-side only, a deliberate layered architecture was used:

```
UI Layer (ui.js)
     ↓
Business Logic (auth.js, voting.js)
     ↓
Data Layer (store.js – DataStore class)
     ↓
Persistence (localStorage)
```

This design makes a future migration to a real backend (Node.js + database) straightforward.

### 4.4 Security & Robustness
- Organizer demo password is compared using the Web Crypto SHA-256 API; this is an educational demonstration only because the hash and client logic are public.
- HTML escaping (`esc` function) is used when rendering user-generated text.
- Registration and photo submission include input validation and type checks.
- Malformed stored database structures fall back to seeded demo data.
- Storage write failures are handled without leaving a newly added vote or photo in memory.

### 4.5 Innovation & Technical Complexity
- **Procedural SVG generation** (`makeArt`) using seeded RNG – unique demo photos without external images.
- **Canvas-based dominant color extraction** (`palette` function).
- Client-side image compression before storage.
- Smooth animations, masonry layout, and keyboard-accessible lightbox.

## 5. Voting Rule (Critical SRS Requirement)

```js
// From voting.js
if (store.hasVotedInCategory(m.id, photo.category))
  return `You already voted in the ${photo.category} category`;
```

A participant may cast **only one vote inside each category**.  
This is checked both in the UI and in the voting engine.

## 10. Security Boundary and Limitations

This is an educational frontend-only application. The organizer password hash is embedded in client-side JavaScript, participant sign-in is based on a name, and all data is stored in user-editable localStorage. Therefore, SHA-256 hashing in this demo must not be described as secure production authentication, and frontend vote checks cannot prevent a determined user from modifying stored data. Production use requires a backend that verifies identity and authorization, uses a password-specific hash (Argon2id or bcrypt), validates every request, and enforces vote uniqueness transactionally in a database.
